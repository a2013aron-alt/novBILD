# Блоки «Файлы» — прямо в палитре Scratch

В отличие от прошлого патча (панель поверх интерфейса в scratch-desktop), это —
настоящее расширение Scratch: новая цветная категория **«Файлы»** появляется в палитре
блоков точно так же, как «Движение» или «Звук», через официальный механизм extensions
(`scratch-vm/src/extension-support`), которым пользуются штатные Pen, Music, Translate
и т.д.

## Изменённые/новые файлы

- `packages/scratch-vm/src/extensions/scratch3_files/index.js` — новое расширение и его блоки
- `packages/scratch-vm/src/extension-support/extension-manager.js` — расширение
  зарегистрировано в списке встроенных (`builtinExtensions.files`)
- `packages/scratch-gui/src/lib/libraries/extensions/index.jsx` — карточка «Файлы» в окне
  «Добавить расширение» (плюс иконки `files.png`, `files-small.svg`)

## Блоки

| Блок | Что делает |
|---|---|
| **добавить файл** | Открывает системный диалог выбора файла (любой тип), читает его в память |
| **запустить файл [FILE]** | Выбор из выпадающего списка добавленных файлов. Картинка — показывается поверх сцены; звук — проигрывается; текст — сохраняется для блока ниже; всё остальное (.exe, .bat и т.п.) — **реально выполняется через ОС**, если приложение работает под Electron с доступом к путям файлов (как в вашем scratch-desktop), иначе браузер предлагает скачать файл |
| **скрыть показанный файл** | Убирает картинку, показанную предыдущим блоком |
| **имя последнего файла** | Блок-репортер |
| **содержимое последнего текстового файла** | Блок-репортер |

Категория добавляется как обычное расширение — в проекте нажмите «Добавить расширение»
(кнопка ➕ внизу слева) и выберите «Файлы», она появится в палитре как отдельная секция.

## Как собрать и проверить

```bash
npm install          # разрешит workspace-зависимости между всеми пакетами monorepo
npm start             # поднимет scratch-gui в браузере на localhost — здесь удобно
                       # сразу проверить, что категория «Файлы» появилась в палитре
```

## Как получить .exe с этими блоками (используя ранее присланный scratch-desktop)

`scratch-desktop` подключает `scratch-gui` как npm-пакет `@scratch/scratch-gui`, а не
как исходники — поэтому, чтобы новые блоки попали в .exe, нужно собрать этот
репозиторий и указать scratch-desktop смотреть на локальную сборку вместо версии из npm:

```bash
# 1) в scratch-editor-develop — собрать пакет scratch-gui
cd scratch-editor-develop
npm install
npm run build --workspace=@scratch/scratch-gui

# 2) в scratch-desktop — подключить локальную сборку вместо npm-версии
cd ../scratch-desktop-develop
npm install ../scratch-editor-develop/packages/scratch-gui

# 3) дальше как обычно — там уже есть кнопка «Собрать .exe» из прошлого патча,
#    либо из терминала:
npm start                 # проверить в самом приложении
npm run build:win-exe     # получить dist/Scratch ... Setup.exe
```

## Ограничения, о которых стоит знать

- «Запустить файл» по-настоящему **исполняет** произвольный файл (например .exe) только
  когда Scratch работает в Electron с `nodeIntegration: true` — именно так настроен ваш
  scratch-desktop. В обычном браузере (playground на localhost, или сайт scratch.mit.edu)
  ОС ничего исполнять не даёт по соображениям безопасности — там файл просто скачается.
- Показ картинки сделан как HTML-элемент поверх canvas сцены, а не через внутренний
  конвейер костюмов/ассетов Scratch (`addCostume`) — то есть картинка не станет
  настоящим костюмом спрайта и не сохранится внутри `.sb3`. Если нужно именно
  «добавить как костюм» — это отдельная, более глубокая доработка (через
  `vm.addCostume`/`scratch-storage`), скажите, если она нужна.
- Список добавленных файлов живёт только в памяти текущего запуска — при перезапуске
  проекта их нужно будет добавить заново (это осознанный выбор: файлы выбираются live,
  а не встраиваются в `.sb3`, иначе он раздувался бы и переставал быть переносимым).
